02 — what this system is

An advisory signal system that grades itself.

BitReinforceX emits trading signals to Telegram; it never places orders. Every hour it analyses 48 Binance USDT pairs (cycle.SYMBOLS) across the timeframes due at that candle boundary, and sends whatever passes the gate to a customer channel (clean signal) and a dev channel (signal + brain dump + feedback buttons). The whole runtime is one process — python telegram_app.py — running the scheduler, the grader, and the nightly trainer as three asyncio tasks in the same loop, backed by one SQLite file.

Decisions come from four RL voters and one gate. The Indicator agent (no LLM) blends direct signals — Nadaraya-Watson Envelope, Chandelier Exit, AlphaTrend, plus trend triggers — with eight rule-based votes. The News agent scans RAG-grounded headlines with gpt-4o-mini. The Research agent scores five market logics (ecosystem drivers, SPX, money-flow, BTC dominance, DXY). The Derivatives agent reads keyless Binance USDM positioning. The brain (brain/decision_maker.py) aggregates them as a weighted vote Σ w·action·conf with learned priorities — and a regime classifier that deliberately does not vote: it gates which trigger family may emit at all, because a linear vote can't express "NWE is good in ranges and poison in trends".

The loop that makes it self-training: every decision — emitted or not — is recorded with each agent's replayable feature snapshot and ATR-scaled barrier prices; the grader walks the realized path 60 s at a time and labels each prediction by the first barrier touched (triple-barrier), rewards each agent for what it said (+1 / −4 / −1.5 / −1.0), and nightly the system fits a meta-label model, per-timeframe confidence calibration, and empirical-Bayes indicator confidences from its own graded history. Humans can override any grade from the dev-channel buttons — a compare-and-swap makes sure auto and manual never double-apply.

The one philosophy that explains every flagconfig.py · README.md — "ship dark → measure → enable on evidence"

Every risky behavior ships behind an env flag defaulted OFF. It turns on only when evidence flips it — an archived backtest A/B (logs/backtest/*/report.md) or a live shadow period. That is why the codebase is full of always-computed-but-not-always-acted-on values: regime stamps, triple-barrier labels, meta_p, calibrated_conf, final_action_v2 all get recorded on every prediction so the evidence exists before the flag is flipped. Two gate rules were even amended back OFF after the backtest measured them (trend-reversal 0/6, higher-TF NWE 12.5%).

05 — the hourly cycle

One tick, step by step.

What actually happens when the clock hits :30 IST. Steps 1–4 run once per cycle; steps 5–10 run for each of the 48 pairs (concurrency-capped at MAX_CONCURRENCY=5).

Scheduler tick — IST :30 is the UTC :00 candle close telegram_app.scheduler_loop() · signals.is_candle_close_minute()

A 30-second poll fires when the IST minute equals 30. The datetime is converted to UTC before the cascade — Binance candles close on UTC boundaries, and the pre-v3 code cascaded off IST hours, running every 4h/1d/1w analysis hours away from a real close (defect A1). signals.timeframes_due(dt_utc): every UTC hour → [1h]; hour % 4 == 0 → +4h; UTC 00:00 → +1d; Monday UTC 00:00 → +1w.

Hourly RSS ingest — before the cycle, 7-day dedup window ingestion.ingest_all() · rag.RagIndex.ingest()

All 8 RSS feeds are pulled, normalized, and asset-tagged (tag_assets: short tickers like OP/AR only match as $OP/OPUSDT to avoid English-word false hits). Each new item is embedded and cosine-checked (≥ 0.9 ⇒ duplicate) against the corpus of the last 7 days — dedup_window_ts = now − 7·86400 — so a story that resurfaces after a week is legitimately new again. Running ingest before the cycle means this hour's headlines ground this hour's prompts.

Clear the OHLCV cache — one market snapshot per cycle utils/data_fetcher.clear_ohlcv_cache() · called by cycle.run_cycle()

The module-level TTL cache (OHLCV_TTL=300s) means BTCUSDT is fetched once per cycle no matter how many agents ask. Clearing it at cycle start (defect fix A8) guarantees all agents in one cycle see the same frames — without it a mid-cycle TTL expiry could hand different agents different candles for the same pair. Every fetch also drops the in-progress candle (CLOSED_CANDLES_ONLY=true, defect A2): live analysis only ever sees closed bars, exactly like the backtest.

Build the market context — ONCE per timeframe market_context.build_market_context()

The single biggest v1 cost defect: all ~48 pairs re-ran identical market-wide work (~576 LLM calls/cycle). Now computed once per (cycle, TF) into a MarketContext dataclass, using Research's own pure logic methods so values are bit-for-bit what the per-coin path produced:

  • Overall news scan (1 LLM call) grounded in the 8 freshest stored headlines (48 h window), each formatted [3h ago] [tier-1] Title so the model can weight recency and credibility. Wrapped in _SharedOverallNews so every downstream news call reuses it.
  • SPX / DXY scores — Research logic 2/5: with MACRO_PRICES_ENABLED, real 5-day trends (FRED SP500/DTWEXBGS, stooq ^spx fallback) carry 60% and news sentiment 40%; DXY is negated (strong dollar = crypto headwind).
  • BTC dominance level + ROC — CoinGecko level, rate-of-change vs the stored macro_snapshots row ≥ 20 h old, then a new snapshot is written (defect fix A5 — the old BTCDOMUSDT spot fetch never existed and always scored 0.0).
  • Fear & Greed (alternative.me) and the money-flow phase (v1 heuristic or quantitative v2 behind MONEY_FLOW_V2).
  • Ecosystem driver scans — every distinct driver ticker needed by the universe gets 1 indicator decide (cached OHLCV, no LLM) + 1 grounded pair news scan (1 LLM call). With today's 48-pair universe that is 36 distinct drivers, so a full cycle costs ≈ 87 LLM calls (3 market-wide + 36 drivers + 48 pair scans) vs ~576 before. (The docstring's "~73" was computed before the v3 universe swap grew the driver set.)

Per-pair decide() — four voters, one brain brain/decision_maker.DecisionMaker.decide() · cycle.run_cycle() fan-out

Each pair runs the full roster in a worker thread. What each voter actually does:

Indicator agentagents/indicator_agent.py + custom_indicators.py + regime_agent.py · no LLM

1 · Closed-candle frame — 500 candles from the per-cycle cache, standardized.

2 · Regime classify (every decide, gates only when GATE_V2_ENABLED) — ADX(14) + CHOP(14) + realized-vol percentile (rolling std-20 of log returns ranked over 100 bars). Hysteresis walked over the last 50 bars: enter trending at ADX ≥ 25 OR CHOP ≤ 38.2; exit at ADX ≤ 20 AND CHOP ≥ 45; minimum dwell 2 bars between flips. Direction from +DI vs −DI. Not trending ⇒ "ranging" if the exit condition holds cleanly, else "mixed".

3 · Type-1 direct signals — regime picks the set. Ranging/mixed: NWE (event mode: fires only on the bar that crosses out of the band — re-firing requires re-entry, an inherent cooldown; state mode re-fires every bar outside) + Chandelier Exit (ATR-22 × 3.0 stop flip) + AlphaTrend (ATR-14 + MFI ratchet, signal vs 2-bars-ago). Trending: Chandelier + AlphaTrend + supertrend_flip (10, 3 — reuses the type-2 columns, conf 0.65 + distance/ATR) + Donchian 20/55 breakout (prior-window, no lookahead) + squeeze release (BB 20/2 inside KC 20/1.5, released within 3 bars). Merged by learned per-indicator credibility weights (default 0.7; +0.05 on reward, −0.07 on punish, clipped [0.1, 0.95]).

4 · Type-2 rule votes — MA ribbon 20/50 (±2), RSI-14 <30/>70 (±1), MACD histogram sign (±1), Bollinger touch (±1), StochRSI 20/80 (±1), SuperTrend direction (±2), and — behind DIVERGENCE_VOTES on 4h/1d — RSI/OBV pivot divergences (±1 each, MAD-prominence filtered).

5 · Blend — learned type1/type2 weights (default 0.65 / 0.35) combine the two heads; the winning action's share of the score mass is the confidence. The blend snapshot (shares + fired_direct) is what the grader later replays.

News agentagents/news_agent.py · gpt-4o-mini · softmax bandit

Reuses the shared overall scan; runs one pair scan grounded in up to 5 stored headlines for the base asset (48 h, [age][tier]-prefixed). Empty corpus ⇒ hallucination guard: the prompt orders "output Neutral with confidence ≤ 0.4 and do not invent headlines" (defect fix A4). Features: 10-dim — 5 sentiment (overall score, pair score, panic flag, overall bias, pair bias) + 5 typed-event features (strongest bull/bear surprise·tier, hack/regulatory flag, signed ETF/listing, unlock flag — all 0.0 unless NEWS_EVENTS_ENABLED). Action from a 3×F linear softmax bandit (ε = 0.1, lr = 0.1, REINFORCE-style update); confidence = max(overall, pair) LLM confidence. Legacy 5-dim policy files zero-pad-migrate with logits preserved exactly (.bak-5dim backup).

Research agentagents/research_agent.py · 5 logics → 10 features → bandit

L1 ecosystem — primary ecosystem's drivers from the shared context; eco_score = clip(0.6·indicator + 0.4·news). L2 SPX — 0.6·price-trend + 0.4·news (news-only when no price source). L3 money-flow — v1 BTC→ETH→alt heuristic, or v2 quantitative phases (risk_off −1.0 · btc_led −0.8 · eth_rotation −0.2 · alt_breadth +0.7 · else soft blend) using dominance ROC. L4 dominance — ROC/0.02 clipped, level tilt (≥60 ⇒ +0.3, ≤40 ⇒ −0.3) or news fallback; converted to alt-favorability. L5 DXY — like L2 but negated. Plus child trend (MA50/200 ±0.5 each), parent trend (leader or BTC), bias 0.2. Bandit: 3×10 softmax, ε = 0.08, lr = 0.05; confidence = σ(2.5·|winning logit|).

Derivatives agentagents/derivatives_agent.py + utils/derivatives_fetcher.py · keyless

Gated by has_futures() (USDM market list, 24 h TTL). Snapshot per pair — funding history (30), OI change over 6 h, top-trader position L/S, global account L/S — cached 55 min (DERIV_TTL_SECONDS=3300) so the 4h/1d cascade reuses the hourly fetch: 48 × 3 ≈ 144 req/h vs Binance's ~500/5min budget. 8 features in [−1,1]: funding_now (±0.1%/8h saturates), funding z-score, funding-extreme signed against the crowded side (|f| ≥ 0.05%/8h), tanh OI change, OI-price divergence (new longs +0.5 · new shorts −0.5 · short-covering −0.25 · long flush +0.25), tanh-log position/account skews, bias 0.2. Same bandit as Research; conf clamped [0.5, 0.9]. No future / fetch error ⇒ available: false, conf 0.0 — a mathematical no-op in the vote, and NULL feats mean the grader applies no reward.

Brain aggregationbrain/decision_maker.py · Σ w·a·conf

score = Σ weight·action·confidence with action ∈ {buy +1, skip 0, sell −1}. Weights are the normalized learned scores — defaults indicator 3.0 · research 2.0 · derivatives 1.5 · news 1.0 (⇒ 0.40/0.27/0.20/0.13), shifted positive and normalized to 1; setdefault absorbs new voters into old policy files with no migration. Final action: deadzone ±0.05 on the score. final confidence = |score| / Σ(w·conf). Deadzone v2 (A7): a directional call additionally needs conf ≥ BRAIN_MIN_CONF=0.25 — always computed and stored as final_action_v2 (shadow), only drives the action when BRAIN_DEADZONE_V2=true. The derivatives voter is only called when DERIVATIVES_ENABLED; off ⇒ byte-identical 3-voter behavior.

Barrier prices recorded — TP 1.5×ATR, SL 1.0×ATR grading/barriers.barrier_prices() · cycle.py

For every directional final action (emitted or not): entry = the true close of the last closed candle; ATR from the regime snapshot (simple rolling mean of true range, ATR_LEN=14). BARRIER_MULTS: 1h/4h/1d = (1.5, 1.0), 1w = (2.0, 1.25). Buy: TP = entry + 1.5·ATR, SL = entry − 1.0·ATR; sell mirrored. These exact prices are stored on the prediction row — the grader never recomputes them.

Meta shadow stamps jobs/nightly.meta_probability() · apply_calibration() · behind META_SHADOW=true

A prediction-shaped dict is built from the in-flight decision and pushed through the nightly artifacts: meta_p = p(correct) from logs/meta_model.pkl (mtime-cached), calibrated_conf = np.interp over the isotonic knots in logs/calibration.json. Both are None until the artifacts exist — identity shadow, zero effect on emission until META_GATE_ENABLED.

Record the full prediction row persistence.Store.record_prediction()

Everything needed to grade and re-train later, snapshotted at decide time: identity + timing (candle_close_ts = CLOSE epoch of the entry candle, grade_due_ts = close + k·TF), the final action/confidence/score + final_action_v2, per-agent replay payloads (news_feats 10-dim + action_idx, research_feats 10-dim + idx, indicator_blend, deriv_feats 8-dim + idx), regime + regime_feats, atr/tp_price/sl_price, trigger_source (emit reason), meta_p, calibrated_conf, brain_weights, session_id. Skips are recorded too — a skip that misses a move is a gradeable error (−1.0).

Broadcast + durable session telegram_app.Broadcaster.broadcast() · signals.fmt_signal_message()/fmt_brain_dump()

Customer channel gets the clean signal: action, NWE reading, pair, TF, confidence, reason, regime, trigger, calibrated confidence (when present), a one-line derivatives note ("funding +0.031%/8h, OI rising 2.4%, crowded longs — squeeze risk"), and the disclaimer. Dev channel gets the same message + the brain dump (per-agent action/conf, meta_p, NWE direct) + a 3-row inline keyboard: BUY / SELL / SKIP LEARNING · 1.0 / −4.0 / Auto-Assign · CLOSE SESSION. A durable session row is created first (its id rides in the callback data), the dev send retries once, and a session whose dev send failed twice is deactivated — a button-less ACTIVE session would be unreachable forever (fix A8). The previous active session for the same (pair, TF) is superseded; sessions expire after SESSION_TTL_HOURS=12 (keyboard stripped on GC).

06 — grading & learning loop

Judge the path, not the endpoint.

A background task polls every GRADER_INTERVAL_S=60 seconds for predictions whose horizon has printed, fetches the post-entry path, labels it, and pays each agent for what it said. grader.py · grading/barriers.py

grade after k closed candles · 1h: k=3 · 4h: k=2 · 1d: k=1 · 1w: k=1 fixed-horizon θ · 1h ±0.4% · 4h ±1.0% · 1d ±2.5% · 1w ±5% path fetch: first candle whose OPEN == candle_close_ts (close-epoch convention, A-series fix) · retries until k closed candles exist

Triple-barrier, first touch winsgrading/barriers.triple_barrier() — same function live and in backtests

Scans at most k candles after entry. A candle whose range spans both barriers is unresolvable from OHLC alone — the reading is the pessimistic SL-first (ambiguous=true), consistent with the precision-first brand. Fewer than k candles and no touch ⇒ "incomplete" (grader retries later; backtest drops tail emissions). The fixed-horizon ±θ label is always computed and recorded alongside for comparability — path-blind grading flattered NWE by judging endpoints while stop-outs happened mid-path. Legacy rows without barrier prices grade via the fixed-horizon path forever. TB labels only drive rewards when TB_GRADING_ENABLED.

Reward map v2grader.reward_for_v2() · active when TB_GRADING_ENABLED · config REWARD_*

caselabel logicreward
Correct call (incl. skip when flat)predicted == realized (tp ⇒ own direction; timeout falls back to fixed-horizon label)+1.0
Wrong directiondirectional call, opposite realized (sl ⇒ opposite direction)−4.0

The asymmetry is deliberate: a wrong direction costs 4 corrects; sitting in a dead market with a directional call costs 1.5; missing a move is the cheapest sin. Legacy map (flag off): flat +1/−4 on the fixed-horizon label.

The claim CAS — auto vs manual can't double-gradepersistence.claim_grading() · grader.py (fix A8)

The auto-grader runs in a worker thread; a human's Telegram callback lands on the event loop. Both can reach the same pending row. claim_grading() is a single-statement compare-and-swap — UPDATE predictions SET graded=1, label_source=? WHERE id=? AND label_source='pending' — and exactly one caller sees rowcount 1. The auto-grader claims before applying rewards and silently drops the row if it loses. A manual claimer that loses re-reads the row and takes the correction path instead.

Manual feedback flow — human verdict always nets outtelegram_app.handle_callback() → grader.apply_manual_feedback()

1 · Buttons

Row 1 sets the session's true outcome (BUY/SELL/SKIP LEARNING). Row 2 picks the news reward — explicit 1.0 / −4.0 or Auto-Assign (match-based); pressing it applies the grade and closes the session (keyboard stripped). SKIP LEARNING + reward ⇒ session closed, nothing trained. CLOSE SESSION just deactivates.

2 · Pending row

Manual claims the CAS, applies per-agent rewards from the stored snapshots with source manual, records the outcome (no realized_return — the human judged it), and back-fills the session's true outcome.

3 · Already auto-graded

Correction math: for each agent, correction = manual_reward − prior_auto_reward applied on the same stored features, recorded with source correction — the net policy effect equals the human verdict. (The brain's slow priority drift keeps the earlier auto signal — not worth unwinding at LR 0.05.)

Stateless apply_reward — the historic feature-race fixnews/research/derivatives .apply_reward(feats, action_idx, r) · indicator .apply_reward(blend, r)

The original agents trained on self._last_features — with 48 pairs analysed concurrently, the grader would reward agent state belonging to whatever pair ran last. Now every reward replays the exact snapshot recorded at decide time: the bandits update from stored (features, action_idx); the indicator agent replays the stored blend (type-1/2 shares + fired_direct) instead of re-reading its multi-MB predictions log (the old learn() was O(file size) per call and racy). Finally dm.apply_brain_feedback() drifts the brain's priority scores: Δ = (+1 correct / −4 wrong)·conf per agent, learning rate 0.05, news score additionally nudged by the explicit news reward — then weights renormalize. Slow by design: Indicator > Research > News stays stable unless long-term evidence says otherwise.

10 — backtest harness

Simulation is production.

The harness never re-implements strategy logic. At every historical bar it slices the same trailing 500-candle window the live system sees and calls the real IndicatorAgent.decide(ohlcv=window, log=False), the real gate from signals.py, and the real grading/barriers.triple_barrier(). Parity is by construction — and guarded by tests/test_backtest_harness.py.

Closed candles

backtest/data.py drops the final (possibly open) candle from every cached CSV — the exact guarantee the live scheduler has at :30. History cache backfills earlier --start AND tops up forward.

Per-bar windows

window=500 matches the live fetch limit; frames are reset_index-ed to the exact 0-based shape ccxt hands the live agent (chandelier aligns positionally and breaks otherwise).

Shared labeler

Every emission is labeled twice: triple-barrier via the very function the live grader calls, and legacy fixed-horizon ±θ for baseline comparability.

Funnel telemetry

Every suppressed bar is counted under its gate reason — the funnel table in each report shows what the gate is rejecting, not just what it emits.

Deck-audit notes — two verified quirks in this snapshotfound while sourcing this page against f0d9822; both are latent, neither affects today's enabled config

1 · Manual REWARD path couldn't find its prediction. 2 · News bandit was constructed 5-dim. NewsAgent.__init__ builds NewsRL(n_features=5) (news_agent.py:383) while features_from_jsons() emits 10-dim vectors; _pad() truncates them, so the 5 event dims are recorded in the DB but not trained by the live instance. Harmless while NEWS_EVENTS_ENABLED=false (those dims are all 0.0) — FIXED in 2a1747c: the constructor is now NewsRL() (follows N_FEATURES=10; the logit-preserving migration runs on first live load, .bak-5dim backup) and a wiring test asserts the agent's bandit width equals N_FEATURES.
