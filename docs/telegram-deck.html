01 · The cast

Three bots, two channels, one human

Each bot has ONE job. They never talk to each other — the SQLite databases and the shared process are the only glue. All three run inside the single python telegram_app.py process (one asyncio loop, three pollers).

📡 Bot A — Signals

TELEGRAM_BOT_TOKEN · the spine of the process

  • Posts every signal to the customer channel (clean) and dev channel (verbose)
  • Owns the dev feedback keyboard + its button callbacks
  • Hosts the scheduler / grader / nightly background loops
  • No commands. Nobody DMs it.

🤖 Bot B — Control

TELEGRAM_CONTROL_BOT_TOKEN · the Pro product

  • Six on-demand agent commands, DM only
  • Pro-gated + 30 queries/day cap (when membership is on)
  • Member of NO channel — pure DM surface

💳 Bot D — Membership

MEMBERSHIP_BOT_TOKEN · the storefront & doorman

  • /plans → payment → auto-invite; join-request gate on the channel
  • Hourly lifecycle: reminders → kick → winback
  • Admin ops: /grant /revoke /subs (only ADMIN_USER_IDS)

05 · The dev keyboard

One tap trains everything

1
Row 1 — ✅ BUY / ❌ SELL / ➖ FLAT (the verdict) One press records what ACTUALLY happened and immediately grades all four agents AND the brain against it with the active reward map (+1 correct / −4 wrong / −1.5 directional-but-flat / −1 missed move). FLAT is a real, teachable verdict — skip-callers get rewarded, directional calls get the timeout penalty. If the signal was already auto-graded, your tap applies corrections that net every policy to YOUR verdict instead.
2
Row 2 — 🚫 DISCARD (no learning) Closes the session teaching nothing. Sessions also expire after 12h and are superseded by the next signal on the same pair+TF.
You never HAVE to press anything — the auto-grader labels every prediction via triple-barrier within the horizon; buttons confirm or override. The tap answers with the per-agent numbers, e.g. "Trained vs FLAT (manual) news +1 · rese +1 · indi −1.5 · deri −1.5". Answers you may also see: "Prediction still recording — try again in a moment" (tapped within seconds of the signal — session stays alive). Old messages in the channel still carry the legacy two-step keyboard (OUTCOME → REWARD); those buttons keep working.

09 · Limits & gotchas

Telegram platform rules worth knowing

RuleConsequence for us
Bots cannot DM a user firstReminders/invites reach only users who ever pressed /start on Bot D. Every PAYING user has (they bought via DM). But a /grant to someone who never talked to Bot D → the invite DM fails; tell them to /start the bot first.
Bots cannot list channel membersNo retroactive audit possible — which is why every JOIN must pass the database gate (join-request links only, never member_limit links).
No "remove member" APIThe kick is ban + immediate unban — that's the standard idiom; the seat stays rejoinable.
Rate limits ~30 msg/s per bot, ~20 msg/min per channelWhy three bots share the work; a burst cycle never queues behind membership DMs.
Join-request links need the bot onlineIf the process is down, joins wait as pending requests — approved on the next start. Nothing lost.
Tokens are the keys to everythingLive only in .env (gitignored). Leak → @BotFather /revoke → paste new token → restart. Each bot revocable independently.
Never post the invite links Bot D mints into public places — they're per-buyer. The only public link is the channel's own "Request Admin Approval" link, which is safe by construction: the database, not the link, decides who gets in.
