01 — premise

A bot that learns from being right or wrong.

Every hour, at the :30 IST candle close, the system analyses 48 crypto pairs across the timeframes that are due. Each pair runs through three specialist agents into a decision brain; the brain emits a buy / sell / skip with a confidence. Strong signals go to Telegram. Then — and this is the point — N candles later the system fetches what price actually did and rewards or punishes every agent on its own prediction. No human required.

◷

Scheduled

IST :30 candle close. Hourly→1h; every 4h→4h+1h; daily→1d+4h+1h; Monday→+1w.

⌬

Multi-agent

News · Indicator · Research feed a weighted Brain that learns which agent to trust.

↻

Self-grading

Realized forward return vs a per-timeframe threshold → automatic +1 / −4 reward.

✶

RAG-grounded

Real headlines, deduped and embedded, injected into the LLM instead of stale memory.

02 — system design

One process. Six layers. One SQLite file.

A modular monolith was the right altitude for a solo operator: the core optimization is sharing one in-memory market-context object across 48 analyses — a network boundary would re-introduce the cost it removes. Every arrow below is a function call today; each could become a queue later.

03 — the minds

Three specialists, one brain.

Each agent is a small contextual-bandit reinforcement learner with its own persisted policy. They were kept from the original build and edited surgically — the hard-won logic and accumulated learning stayed intact.

N

OpenAI gpt-4o-mini, split into a market-wide overall scan + a per-pair scan. RAG headlines ground the prompt; quiet coins reuse cached sentiment and skip the call.

04 — the centerpiece

It trains itself on realized price.

Every prediction is recorded with each agent's RL replay payload and a grade-due time. Later the grader replays that exact snapshot — so reward always lands on the right prediction, even under the concurrent 48-pair batch.

RECORD

Snapshot at predict time

News + research feature vectors, indicator blend, brain weights, entry price and grade-due time → one SQLite row.

WAIT

k candles later

The grader (every 60s) pulls predictions whose horizon has printed and fetches the realized candle close.

JUDGE

Forward return vs threshold

r = (closek − entry) / entry. r ≥ +θ → buy, r ≤ −θ → sell, else skip (in-band means skip was right).

REINFORCE

Reward each agent

Stateless apply_reward from the stored payload. +1 correct−4 wrong

Grading parameters tunable in grader.py

TimeframeHorizon kThreshold θ
1h3 candles0.4%
4h2 candles1.0%
1d1 candle2.5%
1w1 candle5.0%

Manual override

The dev Telegram channel can correct any signal — manual beats auto. The grader only auto-grades pending rows; if a human disagrees with an already-auto-graded prediction, a correction reward = manual − auto is applied so the net effect equals the human verdict. Every reward is tagged auto manual correction for audit.

06 — efficiency

The same market work, computed once.

48885

LLM calls per cycle at 48 pairs — ≈6× fewer, 83% less spend. Per-pair marginal cost dropped to exactly one call.

old · per-coin · ~488
new · ~85

Every pair used to re-run the identical market-wide work — the overall news scan, SPX, DXY, BTC dominance, money-flow phase, and per-ecosystem driver sentiment. Now it's built once per cycle into a shared context and read by all 48 analyses. The news overall scan is computed once and reused across every pair scan.

≈ $140/mo → ≈ $18/mo · gpt-4o-mini

07 — root causes

Three bugs, found by reading the source.

Rewards not passing

Telegram clicks loaded for seconds, then nothing — rewards never applied.
Not the app lifecycle. News/Research stored RL features on a shared singleton; the concurrent batch clobbered them, so feedback trained on whatever ran last.
Stateless apply_reward replays the exact prediction from its SQLite record.

pandas_ta is gone

Indicator agent crashed on import; fresh installs failed.
pandas_ta 0.3.14b0 was pulled from PyPI and its GitHub repo deleted — and it breaks on numpy ≥ 2 and pandas 3.
Vendored into the repo (numpy.NaN patched), pinned numpy<2 / pandas<3, reproducible venv.

1h never scheduled

The described "hourly → 1h" path never actually ran.
timeframes_due appended 4h/1d/1w but never 1h.
Cascade rebuilt: hourly→[1h], 4h→[4h,1h], daily→[1d,4h,1h], Mon→+[1w].
